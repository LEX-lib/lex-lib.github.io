The original 39-01 and 39-04 split this code across an additive two-step (`boarder` optional, then
required) so the deployed app was never broken between two Admin UI edits. With **one** production
payment row and **one** active user, that window is a few minutes of downtime you control — not a
migration risk worth four extra human gates.

**Deliberate deviation from D-39-04's "boarder-first, rename-last" sequencing.** The client here writes
`boarder` + `recorded_by` before either exists server-side. Nothing breaks in production while this
plan runs, because prod serves the previously-deployed build, which still sends `user`. The mismatch
window opens when Plan 39-02 renames the field and closes at your next `npm run deploy` immediately
after that sitting. Record this deviation and its consequence in SUMMARY.md.

## Environment facts (established — do not re-derive)

- PocketBase v0.29.x: `createRule` uses `@request.body.<field>`, never the deprecated
  `@request.data.<field>`. Rule denials surface as **400** on create, **404** on view/update/delete,
  and **200 with an empty items array** on list.
- PocketBase v0.23+ removed per-field defaults. Anything the Zod schema guarantees has **no server
  backstop** — a write path bypassing the mapper loses it.
- An unset `maxSelect: 1` relation stores `''`, never NULL.
- `getFullList()` over `getList()` — PB v0.29.x's count path 400s on non-trivial listRule expressions
  (D-31-B). The rewritten rules are more complex than the ones that trip it.
- `dayjs` strict parse is a **no-op** in this repo — `customParseFormat` is never registered, so
  `dayjs(v, 'YYYY-MM-DD', true)` accepts `"2026-02-31"`. Use the native UTC round-trip check that
  `paymentSchema.ts` already establishes.
- Tailwind utilities lose to PrimeVue's unlayered runtime CSS — breakpoint utilities go on a plain
  wrapper, never on a PrimeVue component.
- **Run unit tests as `npm run test:unit -- --exclude '**/.claude/**'`** — an orphaned worktree at
  `.claude/worktrees/agent-ac578daf1cb97362c/` holds byte-duplicate specs that inflate the count.
- `git status` shows ~40 modified `src/` files that are **CRLF line-ending artifacts only**
  (`git diff --stat` confirms zero content change). Do not commit them, do not "fix" them. Scope every
  `git add` to the files your task actually edited.
