## Visual Hierarchy

**`BoarderRosterView` primary screen focal point: the row list, not the CTA.** The "Add Boarder" button sits top-right of the header row (same position as `PaymentLog.vue`'s "Log a Payment") but is deliberately unaccented in visual weight beyond PrimeVue's default primary Button styling — it is a small, `size="small"` action, not a hero element. The eye lands first on the row list because that is the roster's actual content and the reason an admin opens this tab (checking who's on the roster, tags, active/inactive state); the CTA is a secondary, always-available action for the comparatively rare "add a new boarder" moment. This mirrors the existing `PaymentLog.vue`/`MonthlyReport.vue` precedent, where the list is the dominant visual mass and the action row above it is compact and low-emphasis by comparison.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 (Tailwind `text-sm` default ~1.43, rounds to the project's existing muted/detail text) |
| Label | 14px (`text-sm`) | 500 (`font-medium`) | 1.5 |
| Heading | 16px (effective — inherited container size; see verification below) | 500 (`font-medium`) | 1.3 |
| Display | not applicable this phase — the only display-scale text (`PayTimeApp.vue`'s `h1`) is untouched by Phase 38 |

**2 weights, verified no regression:** `node_modules/tailwindcss/preflight.css:74-81` sets `h1..h6 { font-size: inherit; font-weight: inherit; }` — Tailwind's own preflight makes a heading's size and weight two *independent* resets, each only overridden by an explicit utility class. `PaymentLog.vue`'s `<h3 class="font-semibold">My Payments</h3>` has no size class, so it inherits its ambient 16px (no ancestor sets a smaller `text-*`), while `font-semibold` only overrides *weight* to 600. That means the section header is already visually distinguished from the 14px `text-sm` label/body tier **by size (16px vs 14px) independent of weight** — dropping the header's weight from 600 to 500 does not collapse the hierarchy, because the size delta alone still carries it. Phase 38's new header row (`BoarderRosterView`'s "Add Boarder" title + CTA, mirroring `PaymentLog.vue`'s header+button row) therefore uses `font-medium` (500), matching every label. **Declared set: 400 (body/muted) and 500 (labels + the one section heading).** No 600/700 weight is used by any file this phase creates or modifies.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-surface-page` (`#f5f7fa` light / `#0d1117` dark) | Page background behind the Admin tab and its sub-tabs |
| Secondary (30%) | `--color-surface-card` (`#ffffff` light / `#1a1a2e` dark) + `--color-surface-divider` (`#e8ecf2` / `#2a3142`) | Roster row cards, `ManageBoarder` Dialog surface, row borders/dividers |
| Accent (10%) | PrimeVue preset primary — navy `#002244` light / amber `#e89820` dark (`src/main.ts` `MyPreset`) | Reserved for: the "Add Boarder" primary Button, the active/focused sub-tab indicator (By Boarder / Boarders), and any focused input ring. Never used for row backgrounds or static badges. |
| Destructive | `--color-status-error` (`#c0392b`, theme-independent) | Reserved for: the Delete row-action icon Button (`severity="danger"`) and the delete-confirmation dialog's `acceptProps` — nothing else in this phase uses it |

**Additional semantic assignment (Claude's discretion, per CONTEXT.md):**
- Assigned tag chips (`ROSTER-02`): `Tag severity="info"` (`--color-status-info`, `#378add`) — visually distinct from both the accent-colored primary action and from D-38-16's locked `Tag severity="secondary"` "Inactive" badge. Keeps the 10%-accent budget reserved for actions, not data chips.
- "Inactive" badge: `Tag severity="secondary"` (locked, D-38-16) — muted, not the destructive color; deactivation is reversible, never framed as an error state.

Accent reserved for: **"Add Boarder" button, active sub-tab indicator, focused input/Select ring.** Never for the "Inactive" badge, assigned-tag chips, or row backgrounds.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Add Boarder" (icon `pi-plus`, mirrors the existing "Log a Payment" button exactly — label placement, icon, `size="small"`) |
| Empty state heading | (none — this project's established empty-state pattern is a single `text-sm opacity-70` line, not a heading+body split; see `PaymentLog.vue`'s "No payments logged yet.") |
| Empty state body | "No boarders yet. Add the first one to get started." |
| Error state (load) | "Failed to load roster." — toast only, no inline error block (matches `PaymentLog`/`MonthlyReport`'s existing load-failure convention) |
| Error state (save) | "Failed to {save/update} boarder: {field}: {detail}" — reuses `ManagePayment.vue`'s `describeSaveError()` unwrap verbatim; inline per-field `Message` components render Zod's own messages first |
| Destructive confirmation — Delete | Header: **"Delete boarder"**. Message: **"Delete {displayName}? This cannot be undone."** `acceptProps`: label "Delete", `severity="danger"`. `rejectProps`: label "Cancel", `severity="secondary"`, `outlined`. Exact structural mirror of `PaymentLog.vue`'s `deletePayment()` `useConfirm` call. |
| Deactivate / Reactivate | No confirmation — reversible action. Kebab menu label swaps "Deactivate" ↔ "Reactivate" based on `is_active`; icons `pi-ban` / `pi-check-circle`. |
| Tag creation affordance (D-38-03) | `Create tag: "{typed}"` — the exact, deliberate-click label; matching existing tags are listed above it, not merged with it |
| Account link picker (D-38-12) | First option, always present: **"No account"**. Dropdown filter placeholder: "Search by name or email". Option rows display `name || email`. |
| Tab labels | Top-level: **"Admin"** (renamed from "Monthly Report", D-38-06). Sub-tabs: **"By Boarder"** (default, D-38-08), **"Boarders"** (new). |

## UI Considerations

Applicable state considerations resolved: 10 covered, 3 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | BoarderRosterView (list-collection) | ✅ covered | Zero-boarder roster renders the Empty state body row above (`text-sm opacity-70`), matching `PaymentLog.vue`'s existing single-line empty-state convention. |
| loading | BoarderRosterView (list-collection) | ✅ covered | While `useBoarderRoster`'s shared fetch is in flight, renders "Loading…" (`text-sm opacity-70`) — identical to `PaymentLog.vue`/`MonthlyReport.vue`'s existing `isLoading` pattern. |
| error | BoarderRosterView (list-collection) | ✅ covered | Roster fetch failure surfaces the Error state (load) toast copy above — no inline error block, matching the toast-only pattern already used for `paytime-payments-list`/`paytime-report-list` failures. |
| populated | BoarderRosterView (list-collection) | ✅ covered | Typical ~6-boarder roster renders as a vertical stack of `PaymentLog`-style row cards (D-38-17), one boarder per row, inactive rows sorted after active (D-38-16). |
| partial | BoarderRosterView (list-collection) | ✅ covered | A boarder with zero tags renders with no Tag chips (no placeholder chip); a boarder with no linked account renders with no extra badge — both are valid steady states, not errors (Phase 38 ships no user-facing consequence for an unlinked boarder, D-38-14). |
| zero-one-many | BoarderRosterView (list-collection) | ✅ covered | No singular/plural copy dependency — row-per-boarder reads identically at 1 or many, same as `PaymentLog.vue`'s existing row-list pattern. |
| overflow | BoarderRosterView (list-collection) — many tags on one row | 🧪 backstop | A boarder row with many assigned tags wraps its Tag chips onto multiple lines (`flex-wrap` on the chip container) rather than clipping or truncating. New UI surface, not yet exercised against a precedent. |
| long-text | BoarderRosterView (list-collection) — long display name | 🧪 backstop | An unusually long display name wraps within the row's flexible name column (reuses the `min-w-0` pattern already applied to `PaymentLog`'s notes field) rather than overflowing the row or pushing actions off-screen. |
| loading | ManageBoarder (form) | ✅ covered | Save-in-flight disables the Save button and shows PrimeVue's built-in `:loading` spinner, mirroring `ManagePayment.vue`'s `isSaving` guard exactly. |
| error | ManageBoarder (form) | ✅ covered | Zod validation failures render inline per-field `Message` (`severity="error"`) exactly as `ManagePayment.vue`; save failures surface via the Error state (save) toast copy above. |
| partial | ManageBoarder (form) | ✅ covered | Editing a boarder with no tags/no linked account pre-seeds `tags: []` / `user: null` cleanly on open (mirrors `ManagePayment.vue`'s `watch([visible, record])` seed-on-open effect) — no placeholder text needed. |
| long-text | ManageBoarder (form) / Create-tag affordance | 🧪 backstop | A newly-typed tag wraps within the input row rather than overflowing the dialog; the "Create tag: …" label truncates the typed value with an ellipsis beyond ~30 characters. Exact threshold is new UI, unverified against a precedent. |
| overflow | Admin sub-tab nav (By Boarder / Boarders) | ✅ covered | The nested Tabs use PrimeVue's `scrollable` prop, mirroring the parent `PayTimeApp.vue` Tabs — narrow-viewport overflow is handled even at 2 labels today (3 once Phase 41 adds Ledger). |
