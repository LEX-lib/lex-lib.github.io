The edge probe returned `category: "unclassified"` for ROSTER-06 in this plan's scope. It is
**not** auto-backstopped and **not** dismissed — it is recorded here as an explicit assumption:

- **ROSTER-06 (unclassified) — assumption:** "any authenticated user can read the roster, only
  an admin can change it" is treated as a **binary role predicate with exactly two classes**
  (authenticated-and-`is_admin`, authenticated-and-not-`is_admin`) plus the unauthenticated
  case. No third class (PB superuser, service token, API-key caller) is modelled, and the
  read surface is assumed to be all-or-nothing per row — there is no field-level read
  restriction, so an authenticated non-admin can read every boarder's `name`, `tags`, `user`
  and `is_active`. If a field-level restriction is later wanted (e.g. hiding `tags` from
  non-admins), that is a new requirement, not a gap in this plan.

| unauthenticated internet → PocketBase `paytime_boarders` API | Untrusted, tokenless requests reach the collection directly; the `listRule`/`viewRule` predicate is the only thing standing between them and the roster |

| `users` collection → `paytime_boarders.user` relation | Deleting an account crosses into boarder data; `cascadeDelete` decides whether the boarder survives |
